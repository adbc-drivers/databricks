# Learning journal 2026-11-18

### 2026-11-18: C# telemetry — Telemetry emitted after a `using` reader is disposed must read captured values, not live object state
**Context:** PR #783 — `IsCloudFetchActive` was derived from `_activeReader is CloudFetchReader`, which returns false after Dispose, so statement telemetry (often built after the `using` reader is disposed) reported INLINE_ARROW instead of the real CloudFetch result format.
**Rule:** Record result-format and metrics flags into a field at reader-selection time so they survive Dispose, because statement telemetry is frequently emitted after a `using` reader is disposed; never derive such flags from live reader object identity.

### 2026-11-18: Bot config / supply-chain pins — A new config key is inert unless the pinned engine SHA actually reads it
**Context:** PR #781 added `retrospective.pr_title` to `.bot/config.yaml`, but the key does nothing unless the workflow's `ENGINE_REF` pin is bumped to an engine commit that consumes it, and reviewers flagged that the learning workflow still shared the old pin.
**Rule:** When adding a config key consumed by a pinned external engine, bump that workflow's engine pin to a commit that reads the key and document any intentional divergence from the other pins, or the key is silently ignored.

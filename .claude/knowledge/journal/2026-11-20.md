# Learning journal 2026-11-20

### 2026-11-20: CloudFetch and streams [lang=csharp] — Make a mid-stream read failure sticky so a swallowed error isn't mistaken for EOF
**Context:** In PR #773 the CloudFetch reader threw on a row-count shortfall, but after cleanup a later ReadNextRecordBatchAsync returned EOF on SEA (or continued with later files on Thrift), so a caller that caught the exception saw a partial result as a clean end; the fix stores the DatabricksException and rethrows it at the start of every subsequent read.
**Rule:** When a streaming reader throws partway through, store the error and rethrow it on every later read so a caller that swallows it cannot mistake the remaining/empty stream for a clean end-of-results.

### 2026-11-20: Telemetry and tracing [lang=csharp] — Don't record stream events on Activity.Current when the consumer reads after execute returns
**Context:** In PR #773 the SEA inline reader emitted its row-count-shortfall event on Activity.Current, which is null while the caller consumes the stream after ExecuteQuery, so the report-only shortfall was silently dropped from traces.
**Rule:** Record trace/metrics events for data consumed lazily via the statement's own tracer or a dedicated activity, never Activity.Current, because Activity.Current is usually null when the caller reads the stream after the execute call returns.

### 2026-11-20: Connections and feature flags [lang=csharp] — Build the feature-flag validator registry with a case-insensitive comparer
**Context:** In PR #773 the feature-flag validator registry used a case-sensitive dictionary while merged connection properties are OrdinalIgnoreCase, so a malformed server flag pushed with different casing skips validation, reaches the throwing boolean getter, and breaks CloudFetch reads.
**Rule:** Build any registry keyed by connection/property names with StringComparer.OrdinalIgnoreCase so a differently-cased server value cannot bypass validation that the merged (case-insensitive) property bag would otherwise apply.

### 2026-11-20: CloudFetch and streams [lang=csharp] — Check declared rows before skipping an empty/null batch in completeness accounting
**Context:** In PR #773 a Thrift batch with RowCount>0 but an empty or null payload was skipped before any shortfall check, and _currentBatchExpectedRows was then overwritten by the next batch, so the missing rows escaped both telemetry and the fail-on-mismatch throw.
**Rule:** When accounting for completeness over a stream of batches, run the declared-row shortfall check before skipping an empty or null-payload batch, since the expected count is lost once the next batch overwrites it.

### 2026-11-20: Go driver [lang=go] — Distinguish an unset option from a malformed one when parsing a list value
**Context:** In PR #775 parseScopes treated a non-empty separators-only value such as ",,," as unset and silently fell back to the all-apis default, which a reviewer flagged as hiding a user mistake; the fix returns StatusInvalidArgument when the value is non-empty but yields no tokens.
**Rule:** When parsing a delimited option value, treat a blank value as cleared/unset but return an InvalidArgument error for a non-empty value that yields zero valid tokens, rather than silently falling back to the default.

# Learning journal 2026-11-21

### 2026-11-21: Go driver — Match a workspace host against cloud DNS zones using the bare hostname, not a URL that may carry a port
**Context:** PR #777 added azure-client-secret auth; NewDatabase defaults the port to 443, so the SDK received a URL ending in ':443', the suffix match against Azure DNS zones found no match, fell back to AWS metadata, and the Entra ID endpoint came out empty (login failed with the default config).
**Rule:** When resolving a cloud environment by matching a workspace host against known DNS-zone suffixes, match the bare hostname with the port stripped, and add a test covering the public NewDatabase defaults (not just handcrafted structs).

### 2026-11-21: Go driver — Normalize a hostname before suffix-matching DNS zones
**Context:** PR #777's azureEnvironment used strings.HasSuffix against zones without normalizing; reviewers repeatedly flagged that an upper-case or trailing-dot FQDN sovereign-cloud host falls through to the public Azure authority because url.Hostname() does not lowercase and HasSuffix is case-sensitive.
**Rule:** Lowercase the hostname and trim a trailing '.' before any case-sensitive suffix match against DNS zones, since DNS names are case-insensitive and may arrive in FQDN form.

### 2026-11-21: C# driver — Preserve source priority when adding a fallback to a multi-source lookup
**Context:** PR #502 added a /sql/protocolv1/o/<wsid>/ cluster-path fallback to csharp ParseOrgIdFromProperties; the first cut returned Path's path segment before checking Uri's authoritative ?o= query param, silently changing the prior query-first ordering when Path and Uri disagree.
**Rule:** When adding a lower-priority fallback to a lookup that reads several sources, check the authoritative signal on every source before any source's fallback, and add a test where the sources disagree.
